## 面试追问与回答要点

### 1. 你训练的是 Agent，还是模型？

更新的是模型参数；采样过程依据 Agent 的工具交互轨迹。每轮模型决定动作，环境执行并产生反馈，再进入下一轮 prompt，最终执行结果给奖励。应用编排和工具实现本身不是可学习参数；应用回接要保留训练的观察和动作协议。

### 2. 与普通文本 SFT / RL 的区别？

本项目的数据单位是多轮工具轨迹，有真实执行环境、公开反馈、终局验收与基础设施有效性。SFT 对 assistant response 计算监督损失；RL 只对模型实际生成 token 应用训练 mask，工具观察属于下轮 prompt，不能把工具输出当成模型生成内容训练。

### 3. 为什么先 SFT，再 GRPO？

初始小诊断中 Base 在 train/dev 各 0/16，工具契约合法率不足，train 同题组无奖励差异。先用 315 个 train-only 样本完成 80 次 LoRA 更新，让格式和基本修复可用；SFT 后 train 2/4 组出现奖励差异，再进入 RL。完整 Base/SFT dev 的变化不能归因于 GRPO。

### 4. GRPO 的组是怎么构造的？

同一个任务采样 4 条完整轨迹，比较各自终局 0/1 奖励。实际 batch 每次含 4 个同题组、16 条轨迹。审计实现以 `(R - 组均值)/(组标准差 + 1e-6)` 检查真实优势，并将轨迹级优势对应到该轨迹的各轮生成 token；这不是把不同题的奖励混作一组。见 `code_repair/day8_audit.py`。

### 5. 为什么不能看到奖励为 1 就认为还有学习信号？

若同题四条都得 1，组内相对优势为 0；全部失败同样没有相对排序信号。KL 项仍可能产生梯度，所以“参数在变”也不等于在获得有效的相对奖励收益。第 75 个 batch 触发连续五批无差异保护，在执行第 75 次更新前退出；实际更新到 74，最后完整保存到 70。

### 6. 为什么选 step70，不坚持跑满？

已有停止保护、checkpoint 完成标记和冻结 dev 协议。先评估最新完整的 step70，而非修改停止阈值追求步数。不能宣称 70 步最优或已经收敛；后续若改数据、采样或继续到 225/255，另建实验记录。

### 7. 怎么避免训练和测试泄漏？

按 MBPP 原题 source_id 划分，变体不跨 split；提前冻结 50 个 test 来源，选模与配置冻结后构建测试，经模型无关过滤保留 42 个来源。运行时模型只见公开任务和公开测试，私有输入与期望值留在独立服务。这里的私有是运行时可见性隔离，并不声称题目对公开预训练语料绝对未知。

### 8. 独立测试的提升大吗？能证明泛化吗？

只观察到 90/126 → 93/126，配对改善 7、退化 4，约 +2.38 个百分点。三次 seeds 相关，未做显著性检验，任务规模小，不声称稳定普遍提升。若继续研究，应增加独立来源和任务难度、做按原题聚类的不确定性分析；不能反复根据已看过的同一 test 调参再称盲测。

### 9. 为什么应用 dev 和原 dev 分数不同？

一个用 Transformers SDPA，另一个用 vLLM，随机流与数值实现不同。本项目分别在每个后端比较相同协议的 SFT 与 step70；不能拿 vLLM 的 75 对 Transformers 的 63 宣称提升 12 次。

### 10. 为什么不直接给模型 ZzhClaw 所有工具？

训练仅包含三个受限 JSON 工具。开放 Shell、联网、任意目录及技能注入会改变训练分布，也扩大执行范围。当前单独实现受限 CLI profile，复用共享 runner，而非声称已经完成通用 UI / 工具集迁移。

### 11. 如何处理模型失败与基础设施失败？

错误修复、格式不合法、公开测试失败后主动结束，正常计 0 分并消耗预算。SSH 隧道、评价服务或模型 API 故障单独记无效尝试，不进入训练优化，也不当正常模型失败。应用 dev 在 55 条后隧道中断，保留已完成配对并从缺失条目恢复，没有静默丢弃异常。

### 12. 关机后可以无损续训吗？

权重、scheduler / RNG / data 游标可以保存，但本次不保存 Adam 动量，以减少存储。恢复后重建优化器，不能承诺与不中断训练逐位等价。模型推理只需完整 HF 导出目录；继续实验还应保存原 checkpoint、身份文件、代码与数据指纹。

### 13. 能展示失败案例吗？

可以：`regression` 展示 SFT 正确、step70 错误的阶乘末位任务；`shared-failure` 展示两个模型都未满足尾字母大写且在公开测试失败后结束。它们与 LIS 修复的正向案例一起保留，案例不是随机样本，结论依赖完整配对统计。

### 14. 你现在还有哪些没完成？

原 225 步训练计划没有跑完；完整权重实例外备份未验收；通用真实仓库/全工具集/UI 泛化、反馈消融和统计显著性分析未完成。当前交付是受限代码修复训练原型、独立测试和 CLI 迁移闭环。第 15 天演示为可执行的记录回放，并非新录制的 GPU 推理视频。
